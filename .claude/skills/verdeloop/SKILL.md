# Verdeloop

เว็บขาย **หลอดดูดน้ำจากชานอ้อย ย่อยสลายเองได้ (Home Compostable)** สำหรับลูกค้า B2B

## ⚠️ ข้อแรกที่ต้องรู้: Verdeloop ไม่ใช่รีแบรนด์ของ SmartBio

**Verdeloop เป็นแบรนด์ของ "บริษัท ทองกร46 จำกัด" — คนละนิติบุคคลกับ 2AM Plus (เจ้าของ SmartBio)**

เดิมทีเข้าใจว่าเป็นบริษัทเดียวกันรีแบรนด์ตัวเอง จนเจ้าของแจ้งชัดเมื่อ **8 ก.ย. 2569** ว่า
*"301 redirect จาก 9 URL ไม่เกี่ยวเพราะเว็บเดิมจะยังคงอยู่ ให้ตัดเรื่อง 2 เว็บออกจากกันเลย"*

ผลที่ตามมา (ทำไปแล้วทั้งหมด):
- **เว็บเดิม `2amplus.com/smartbio` ยังเปิดอยู่ ไม่ได้ปิด** → งาน 301 redirect **ถูกยกเลิก** ไม่ต้องทำ
- **ห้ามอ้างถึง SmartBio หรือ 2AM Plus ในหน้าเว็บเด็ดขาด** — ไม่มีบรรทัด "เดิมชื่อ SmartBio" อีกแล้ว
- **ห้ามใช้เบอร์ อีเมล ที่อยู่ หรือ LINE ของ 2AM Plus** ทุกจุดในเว็บ (ตรวจแล้วไม่เหลือแม้แต่ที่เดียว)
- ad group "แบรนด์เดิม" (ซื้อคำว่า SmartBio) **ใช้ไม่ได้แล้ว** — เป็นแบรนด์ของบริษัทอื่น การ bid ทับ
  แล้วพาคนมาเว็บเรา สุ่มเสี่ยงทั้งข้อกำหนดเครื่องหมายการค้าของ Google Ads และกฎหมายเครื่องหมายการค้า

- แบรนด์: **Verdeloop** (*verde* เขียว + *loop* วงจรหมุนเวียน — สื่อการ upcycle ชานอ้อย)
- โดเมน: **`verdeloopthailand.com`** (เช็คแล้วว่าง ก.ย. 2026 · **ยังไม่ได้จด**)
  - `verdeloop.com` **ถูกจดแล้ว** (3 พ.ย. 2024, IONOS SE, เจ้าของอยู่ UK, เป็นหน้า parking เปล่า)
  - ที่ว่างอยู่ด้วย: `verdeloop.co`, `verdeloop.co.th`, `verdeloop.net`, `verdeloopth.com`
- ภาษา: **ไทยอย่างเดียวก่อน** (อังกฤษไว้ทีหลัง)

## 1. เป้าหมายของเว็บ (เจ้าของเลือกไว้ 4 ข้อ)

เรียงลำดับที่ควรทำงานร่วมกัน:

```
ติดอันดับ Google  →  ดูน่าเชื่อถือ  →  ทัก LINE / กรอกฟอร์ม
   (พาคนเข้ามา)      (ทำให้เชื่อ)      (เก็บลีด)
```

1. ติดอันดับ Google — คำเป้า: หลอดชานอ้อย, หลอดกระดาษเปื่อย, หลอดย่อยสลายได้, หลอดรักษ์โลก

4. เก็บลีดผ่านฟอร์มขอตัวอย่าง

> เว็บเก่าพลาดตรงยัด CTA ตั้งแต่บรรทัดแรกโดยยังไม่พิสูจน์อะไร — เว็บใหม่ต้องพิสูจน์ก่อนขอ

## 4. ปัญหาของเว็บเก่า (สิ่งที่เว็บใหม่ต้องแก้ ไม่ใช่แค่ทำให้สวย)

1. **จุดขายแรงสุดถูกฝัง** — คนเปลี่ยนจากหลอดกระดาษเพราะ "เปื่อยยุ่ย" แต่เว็บเก่าพูดผ่าน ๆ
2. **ไม่อธิบาย Home vs Industrial Compostable** — นี่คือคูเมืองที่ PLA เลียนแบบไม่ได้ แต่ลูกค้าไม่รู้ เลยเทียบแค่ราคา
3. **ไม่มีราคาเลย ทุกอย่างต้องทัก LINE** — คนที่ยังไม่พร้อมแชทหลุดหมด
4. **ขาดข้อมูลที่ผู้ซื้อ B2B ต้องรู้** — ไม่มีความหนาผนัง ไม่มี FAQ ไม่มีตารางเทียบ ไม่บอกว่าแช่น้ำได้นานแค่ไหน (คำถามแรกของทุกร้าน) ไม่มีอายุการเก็บ
5. **HTML พัง กระทบ SEO** — หน้า hub มีแค่ `<h5>` หน้าสินค้ามี `<h3>` เดียว ที่เหลือเป็น div ล้วน
6. มี typo ค้าง (`Institue`) และลิงก์เสีย (`http:// https://...`)

## 7. ข้อมูลติดต่อ (เจ้าของให้มา 8 ก.ย. 2569)

แหล่งความจริงเดียวคือ `CONTACT` ใน `src/data/products.ts` — ทุกหน้าอ่านจากตรงนั้น ห้าม hardcode ที่อื่น

```
บริษัท ทองกร46 จำกัด
13/221 หมู่บ้านเมืองทองนิเวศน์ 1 ซอยแจ้งวัฒนะ 14
แขวงทุ่งสองห้อง เขตหลักสี่ กรุงเทพฯ 10210
LINE OA : @verdeloop
โทร     : ⚠️ ยังไม่มี — เจ้าของบอกว่ามีเบอร์ใหม่แต่ยังไม่ได้ส่งมา
อีเมล    : ⚠️ ยังไม่มี — รอจดโดเมนก่อน แล้วจะใช้ info@verdeloopthailand.com
```

**`phone` / `phoneHref` / `email` เป็น `null` อยู่ตอนนี้ และทุกหน้า null-guard ไว้หมดแล้ว**
ช่องทางโทร/อีเมลจะ *หายไปทั้งก้อน* ไม่ใช่โผล่มาเป็นลิงก์เปล่า และจุดที่เคยให้โทรนำ
(hero หน้าแรก · กล่อง error ของฟอร์ม · ใต้ปุ่มส่ง · หน้า thank-you · หน้า privacy · เมนูมือถือ)
สลับให้ **LINE ขึ้นมาเป็นช่องทางหลักแทน** ไม่มีจุดไหนเหลือช่องว่าง

พอได้เบอร์จริงมา ใส่ที่ `CONTACT` ที่เดียวจบ ทุกหน้าจะโผล่ปุ่มโทรกลับมาเองพร้อม `data-track="phone"`

> **ห้าม deploy จนกว่าจะมีอย่างน้อยเบอร์หรืออีเมลจริง** — ยิงแอดโดยมีแค่ LINE เป็นช่องทางเดียว
> จะเสียลีดกลุ่มฝ่ายจัดซื้อองค์กรที่ต้องมีอีเมลไว้ออกเอกสาร

| ที่อยู่ | ใช้ที่ไหน |
|---|---|
| `/img/hero-straws.webp` + `@2x` | hero หน้าแรก (LCP — `fetchpriority=high` ห้าม lazy) |

**วิธีลบพื้นหลัง: flood fill จากขอบภาพเข้ามา ห้ามใช้ threshold ทั้งภาพ**

## กติกา CSS ของโปรเจคนี้ (ห้ามพลาดซ้ำ)

**กฎ CSS ที่เขียนเองต้องอยู่ใน `@layer` เสมอ**

Tailwind v4 ใช้ cascade layer ตัดสินก่อน specificity — กฎที่อยู่นอกทุก layer จะชนะ utility ทั้งหมด
เคยพลาด: เขียน `h1 { font-family: Pridi }` นอก layer แล้ว `class="font-sans"` ทับไม่ติด
(เจ้าของเห็นว่าหัวข้อเป็นคนละฟอนต์กับที่โค้ดสั่ง) เช่นเดียวกับ `p { line-height: 1.85 }` ที่กิน `leading-*` ทุกตัว

```css
@layer base { /* ค่าเริ่มต้นของ element: html, body, p, h1-h6 */ }
@layer components { /* คลาสของเราเอง: .eyebrow .tick-rule .index-num */ }
```

ลำดับที่ถูกต้อง: `properties → theme → base → components → utilities` (ท้ายสุดชนะ)

**ฟอนต์เรียกจาก `<link>` ใน Base.astro ไม่ใช่ `@import` ในไฟล์ CSS**
`@import` ทำให้เบราว์เซอร์ต้องโหลด CSS เสร็จก่อนจึงเริ่มโหลดฟอนต์ (โหลดต่อกันเป็นทอด) ดัน LCP แย่ลง
ซึ่ง LCP เป็นตัวจัดอันดับของ Google — โปรเจคนี้ทุกอย่างต้องรับใช้ SEO

**ฟอนต์เดียวทั้งเว็บ: `IBM Plex Sans Thai`** (เจ้าของสั่ง 7 ก.ย. 2569 — "ใช้ font เหมือน h1 hero ทั้งเว็บ")
โหลด 4 น้ำหนัก: 400 เนื้อความ · 500-600 หัวข้อ · 700 เฉพาะ h1 hero
ต้องโหลด 700 ด้วย ไม่งั้นเบราว์เซอร์ปลอมตัวหนา (faux bold) ซึ่งภาษาไทยบวม/ขอบเบลอชัดกว่าละตินมาก
แยกหัวข้อกับเนื้อความด้วย **ขนาด + น้ำหนัก** ไม่ใช่การสลับฟอนต์

เคยลองคู่กับ `Pridi` แล้วไม่เวิร์ค — Pridi มีเชิงเฉพาะตัวละติน ส่วนตัวไทยไม่มีหัวเหมือน IBM Plex
บนเว็บไทยล้วนจึงแทบแยกไม่ออก ได้แค่ไฟล์ฟอนต์เพิ่มมาเปล่า ๆ (พิสูจน์ด้วยการ render ไฟล์ฟอนต์เทียบกันจริง)
token `--font-display` ยังอยู่แต่ alias ไป `--font-sans` — class `font-display` ลบออกจาก markup หมดแล้ว
ถ้าอนาคตจะเปลี่ยนฟอนต์หัวข้อ แก้ที่ `--font-display` บรรทัดเดียวจบ
